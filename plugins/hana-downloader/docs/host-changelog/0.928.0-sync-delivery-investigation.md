# 0.928.0 宿主升级调研（2026-09-08）

宿主从 0.919.4 升级到 0.928.0（用户重启后）。hana-downloader v0.12.0 plugin 自动重载。

## session:send handler 关键行为（0.928.0 L185079-185157）

```js
async ({ text: s, ...i }, o = null) => {
  const a = Mc(o?.caller), ...
  if (a) {
    // v2 app 分支（Mc() 返回非 null）
    if (steer + streaming) → CU (submitDesktopSessionMessage)
    if (followUp + streaming) → followUpSession
    else → ece().completion（真同步）
  } else if (!s || typeof s != "string" || !s.trim())
    throw new Error("text is required");
  // v2 plugin 分支（Mc() 返回 null）
  if (r.isSessionStreaming(f)) throw new Error("session_busy");
  return r.promptSession(f, s, i).catch(...)
}
```

**对比 0.919.4**：0.919.4 底部分支**没有 text 校验**，0.928.0 **新增了** else 分支的 `text is required` 校验（L185084）。

但 plugin 传 `text = <hana-background-result ...>`（非空 string），应该过校验。

## Mc() vs bc() 函数

```js
// 0.919.4 L177420
function bc(t) {
  return !t || typeof t != "object" || t.kind === "plugin" ? null : zn(t.pluginId);
}

// 0.928.0 L185637
function Mc(t) {
  return !t || typeof t != "object" || t.kind === "plugin" ? null : Yn(t.pluginId);
}
```

**完全等价**——只是改名（`bc` → `Mc`, `zn` → `Yn`）。v2 plugin caller 永远返回 null。

## Ef() / resolveSession 行为

L185699: `async function Ef(t, e = {}, r = "session", n = {})` —— 与 0.919.4 同。

## 关键结论

**0.928.0 同步投递口子对 v2 plugin 的行为与 0.919.4 完全一致**：
- `session:send` 走底部分支 → `promptSession(f, s, i)`
- v2 plugin caller 永远走底部分支（Mc() 返回 null）
- 0.928.0 新增了 text 校验，但 plugin 传非空 string 不过影响

**v2 plugin 在 0.928.0 下 session:send 真同步投递仍然应该走 `promptSession` 路径**——和 0.919.4 行为一致。

## 如果 0.919.4 下 v0.12.0 真同步没生效

那 0.928.0 下也不会生效（行为没变）。原因**不在 host**，而在 plugin 端的：
- promptSession 调用对 plugin caller 抛错（preflightSessionInput 校验？）
- 或者 sessionPath 解析错误
- 或者 plugin 端 catch 静默吞错

需要 console.log 诊断。

## 0.928.0 下可能的改进：
1. **deferred:resolve 多 2 处**：可能 host flush 周期变短 → 异步投递更快
2. **0.928.0 与 v2 plugin 兼容**：plugin 自动重载成功（onload 3ms）
