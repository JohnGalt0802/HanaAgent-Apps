## 根因（全部有 bundle 取证，0.928.0 8:27 版）

1. **plugin caller 分支**（bundle L185148-185155）：`isSessionStreaming(f)` 仅在「有 prePromptAbort controller 或 session.isStreaming」时为 true（L29570）。
   - agent 活跃期（连续 turn / loop）恒 busy → 旧版 60×500ms 重试全灭，白等 30s；
   - agent 空闲时其实能通，但空闲时 deferred 的 triggerTurn 行为等价，同步层无增益。
2. **v2 app steer 分支是死路**（bundle L185087-185131）：`deliverAs:"steer"` 确实支持 streaming 中注入，但入口被 `nJr` 归属校验拦住（L185654-185661）：目标 session 必须在 `listSessions({ownerPluginId: <app>})` 里。**主对话 session 不属于任何 app，永久不可达**。sync-probe 实测报错印证：`session "..." does not belong to app "sync-probe"`。
3. **deferred 通道本身就是双向即时**（bundle L124634 + L28495-28518）：
   `deferred:resolve` → store.onResult 订阅 → `deliverTask` 立即执行：
   - busy → `sendCustomMessage(deliverAs:"followUp")` 即刻排队注入本 turn 尾；
   - idle → `UEr(r)=true`（status resolved）→ `triggerTurn` 唤醒新 turn。
   延迟毫秒级，无需插件层做任何等待。

## 改动

- `lib/delivery.js`：删除 `deliverSync`（session:send 60×500ms 重试 + diag 日志写入）、`SYNC_RETRY_*` 常量、`buildEntryText/buildEntryDetails/esc/sleep` 死代码。`handleFinal` 直接 `deliverAsync`（deferred:register + resolve，与 v0.11.0 同接口）。
- manifest `0.12.0 → 0.13.0`。
