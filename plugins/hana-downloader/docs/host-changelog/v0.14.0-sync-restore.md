# v0.14.0 — 真同步投递恢复（bundle 魔改重建 + 插件同步层回填）

日期：2026-09-08（晚） | 状态：**实测确认（两条同步注入样本）**
宿主：0.928.0-win32-x64（bundle 09-08 08:27） | 插件：hana-downloader 0.14.0

## 0. 同步投递的定义（用户口径，本次修复的验收标准）

> agent 正处于**未收束的流式回复过程**中，下载完成后的完成信息拼入**下一条 LLM API 请求**的 messages，
> 这样 Agent 在不收束会话的前提下，在**下一次思考**就能收到下载完成的信息。
> 不是其他任何时间节点的消息注入。

关键区别：deferred 的 `followUp` 是「turn 边界注入」（收束后才轮到），不满足该定义。

## 1. 症状与根因（实测取证）

用户报「宿主更新后同步投递又挂了」。实测确认**两层同时缺失**：

| 层 | 状态 | 取证 |
|---|---|---|
| 宿主 bundle 魔改 | ❌ 丢失 | `Select-String bundle/index.js -Pattern __sessionHooks` 零命中（宿主更新覆盖） |
| 插件同步注入层 | ❌ 已删 | v0.13.0 的 index.js/delivery.js 无 `enqueueSync`/`injectForSession`/`pre-step` 任何痕迹 |

另外实测否掉了一条原本看好的路：

- 0.928.0 bundle L99725 存在 `ctx.hooks.onDecision(...)`，但那是 **v2 app** 的 ctx 成员；
  插件 onload 实测日志：`ctx.hooks=undefined onDecision=undefined` → **v2 plugin 的 ctx 没有 hooks 成员**，
  正门对插件不存在（不是权限问题，是字段不存在）。

结论：**bundle 魔改仍是 v2 插件注册 `agent/pre-step` 的唯一通道**。

## 2. 修复内容

### 2.1 宿主侧（bundle 魔改，工具化）

锚点（0.928.0，唯一命中）：
```js
const se = t.sessionHooks ?? oot();
if (se.registerProviderCapabilities({...}), O.setSessionHooks(se), ...)
```
在锚点语句之后插入：
```js
if (typeof globalThis !== "undefined" && typeof globalThis.__sessionHooks === "undefined") {
  globalThis.__sessionHooks = se;        // sessionHooks registry
  globalThis.__hanaEngine = O;           // HanaEngine 实例
  globalThis.__sessionHooks.isSessionActive = (p) => { /* O.isSessionStreaming(p) */ };
}
```
- 备份：`<workspace>\_temp\bundle-index.js.0.928.0-win32-x64-魔改前.bak`
- **重建脚本**：`<workspace>\_tools\hana-host-patches\ensure-session-hooks-patch.ps1`
  （版本无关锚点正则 + 幂等 marker + 自动备份 + `-DryRun`）
- 已挂进 `restart-hana-reliable.ps1`：每次脚本重启前自动补丁，宿主更新后不再静默丢失。

### 2.2 插件侧（v0.13.0 → v0.14.0）

- `lib/delivery.js`：恢复 pending 队列、`enqueueSync`、`injectForSession`、`tailSettled`、`sessionActive`；
  `handleFinal`/`handleStall` 按会话状态分流：
  - **未收束** → `enqueueSync` 等下一次 `agent/pre-step`
  - **已收束** → `deferred:register + resolve` 异步唤醒（原 v0.13.0 路径保留）
  - 30s 未消费 → 降级异步；魔改暴露 `isSessionActive` 且会话活跃时续等（上限 10 分钟）
- `index.js`：onload 注册 `agent/pre-step` adjudicator（优先 `ctx.hooks`，退 `globalThis.__sessionHooks`），
  注入成功返回 `{ messages }`；onunload 释放。
- `manifest.json`：0.13.0 → 0.14.0。

## 4. 复查钩子（宿主每次更新后）

1. `pwsh -NoProfile -File <workspace>\_tools\hana-host-patches\ensure-session-hooks-patch.ps1`
   —— 返回 `OK: 魔改已在位` 或自动重建（重建后必须重启）。
2. 重启后看 `plugin-data\hana-downloader\v2-load-debug.log`：
   必须有 `registered agent/pre-step adjudicator via globalThis.__sessionHooks`。
3. 若宿主改写了 `const X = t.sessionHooks ?? Y();` 结构 → 脚本会报 `ERR: 未找到 sessionHooks 锚点`，
   需按 §2.1 人工定位新锚点并更新脚本正则。
4. 若宿主某天给 v2 plugin 的 ctx 加上 `hooks` 成员 → 插件会自动切到正门（`ctx.hooks`），
   此时可评估停用 bundle 魔改。
