# 聊天流卡片宽度与容器约束（2026-09-08 排查）

> 宿主 0.930.1 · hana-downloader v0.14.0
> 触发：用户核对「卡片宽度是否按 最大值→跟随缩窄→最小值 的策略」

## 结论

聊天流里的下载卡片宽度**不由插件上报值决定**，而是被宿主的「工具块」容器夹住。

| 环节 | 值 | 来源 |
|---|---|---|
| 插件上报 | `width: 470`（宿主当 maxWidthPx 用，封顶不锁定） | `app/card.js` `CARD_WIDTH` |
| 宿主工具块宽度 | `--chat-task-block-width: 348px` | 宿主 renderer CSS |
| 宿主卡片容器 | `width: 100%; max-width: 100%` | `._card_9070a` |
| 宿主最小宽度支持 | **无**（dist-renderer 全库搜不到 `minWidthPx`） | — |

所以卡片实际宽度 = min(容器宽, 470) = 容器宽。**470 从未生效**。

拆成三条期望：

| 期望 | 现状 |
|---|---|
| 最大值 470 | ✗ 被工具块容器夹住 |
| 聊天区缩窄时跟随缩窄 | ✓ 容器 `max-width:100%` |
| 缩到最小值为止 | ✗ 宿主无 minWidthPx（宿主对聊天框宽度本身有兜底，故不处理） |

## 实测：四并发宽度一致性（0.930.1）

构造：四个并发下载，故意用不同限速让状态各异（即时完成 / 512B·s⁻¹ / 256B·s⁻¹ / 128B·s⁻¹）。

结果：四张卡片**左边缘对齐、右边缘对齐、按钮位置一致、宽度一致**。
卡片比正文窄（工具块设计宽度），属预期，非 bug。

## 旧问题：卡片紧跟思维链被「缩进」

历史现象：卡片紧跟思维链正下方时被宿主当作思维链子块，尺寸变小且无法调整。

**0.930.1 实测：不再表现为额外缩窄。** 紧跟「思考完成」的卡片与普通工具块等宽、左边缘对齐。
（"比正文窄"依然存在，但那是工具块宽度，不是思维链缩进。）

## 若要卡片真正到 470

需要宿主侧支持：提高 `--chat-task-block-width`，或让工具卡片脱离工具块渲染。插件侧突破不了父容器。

短期替代（未采用，用户判定一致性达标即可）：把 `CARD_WIDTH` 调到 ≤348，使上报值与实际渲染一致，避免"报了 470 实际 348"的误导。
