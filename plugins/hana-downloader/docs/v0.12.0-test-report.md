## 关键发现

### ❌ v2 真同步投递（`session:send → promptSession`）未生效

所有 HBR 的 `details.deliveryId` 都是 **`deferred-delivery:`** 前缀，不是预期的 `prompt-delivery:` 或 `steer-delivery:` 前缀。

**根因分析**：
1. v2 plugin caller = `{kind: "plugin", pluginId}` → `bc()` 返回 null
2. `session:send` handler 走底部分支（非 v2 app 分支）：
   ```js
   if (r.isSessionStreaming(f)) throw new Error("session_busy");
   return r.promptSession(f, s, i);  // ← 这里抛错
   ```
3. `promptSession` 内部可能对 plugin caller 抛错（preflightSessionInput 校验失败）
4. plugin `catch (e)` 静默，落 fallback `deliverAsync`
5. `deliverAsync` 调 `deferred:resolve` → 写 deferred store → host 在 agent idle 时 flush jsonl

### ✅ 异步投递（deferred:resolve fallback）工作良好

- done/stall/cancel 三种状态都成功投递
- agent 都收到 HBR（异步延迟 30s-3min）
- tasks.json delivered 标记正确

### ❌ plugin log 通道失效

- host 日志完全没 plugin 自己写的 log（除 plugin-manager 加载）
- v2-load-debug.log 只有 onload 日志，无 [delivery] SYNC/ASYNC 日志
- 可能 `ctx.log` 是 mock（`info() {}`）或 logSink 通道不工作

## v0.12.0 vs v0.11.0 对比

| 维度 | v0.11.0 | v0.12.0 设计目标 | v0.12.0 实际 |
|---|---|---|---|
| plugin 协议 | v1 | v2 | v2 |
| 投递通道 | deferred:resolve async | ~~session:send 真同步~~ | deferred:resolve async (fallback) |
| 延迟 | 30s-3min | < 1s（设计）| 30s-3min |
| enqueueSync 30s timer | 有 | 删除 | 删除 |
| agent/pre-step injection | 有（已废）| 删除 | 删除 |
| 真同步投递 | ❌（sync-first 名不副实）| ✅（设计目标）| ❌（走 fallback）|

**功能上 v0.12.0 == v0.11.0**，但代码更简洁（v2 plugin 协议 + 真同步投递代码保留 + async fallback 工作）。

## 结论

v0.12.0 v2 plugin 升级**核心目的未达成**（真同步投递仍走 fallback），但**功能完整**（done/stall/cancel 都投递成功）。

**建议**：保持 v0.12.0 现状（async fallback 已足够用），除非未来需要优化投递延迟（去掉 30s 重试直接 fallback 可缩短延迟到 host flush 周期）。

## 修复建议（如果用户希望继续优化）

### 1. 去掉 30s 重试，直接 fallback async

`lib/delivery.js` `deliverSync` 改为：
```js
async function deliverSync(t, result) {
  // 0.919.4 下 session:send 对 v2 plugin caller 不接受 → 直接 fallback
  await deliverAsync(t, result);
}
```

这样投递延迟 = host flush 周期（通常几秒），而不是 30s+。

### 2. 加 console.log 诊断（需重启）

```js
} catch (e) {
  console.log(`[delivery] SYNC ERR ${t.taskId}:`, e?.message, e?.stack);
  // ...
}
```

绕过 ctx.log 问题，捕获 session:send 真实错误。

### 3. 深挖 host 对 plugin caller 的 promptSession 行为

读 host bundle `core/session-coord/session-coord.ts` (L28369 promptSession)：
- 看 `preflightSessionInput` 校验什么
- 看 plugin caller 是否被允许走 promptSession
- 看是否需要 caller permission
