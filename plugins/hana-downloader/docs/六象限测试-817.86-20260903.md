## 2. 修复 640f4bd1：stall 异步超时兜底

### 根因（d4ff2989 丢弃）

delivery.js `enqueueSync` 超时兜底（L206-210）对 `kind === "stall"` **只置 `t._stallDelivered = true` 不调 `deliverAsync`**：

```js
if (kind === "stall") {
  t._stallDelivered = true;   // ← BUG：只标记不投递
} else {
  deliverAsync(t, item.result).catch(() => {});
}
```

**触发链**：stall 触发时 agent 未收束（tailSettled=false）→ enqueueSync 入 pending → agent 随后收束（stop=stop）→ pending 无法注入 → 30s 超时 → 掉进 stall 分支 → 只标记不投递 → stall HBR 丢失 → 任务终态（interrupted）又被 handleFinal 的 `stallNotified` 抑制 → **双通道全丢**。

### 修复

1. **新增 `deliverStallAsync(t, result, stallKey)`**：enqueueSync 超时兜底里，stall 走 `deferred:register(占位 stallKey)` + `deferred:resolve` 异步投递（与 handleStall settled 分支同构）。
2. **handleFinal 抑制条件收紧**：从 `(_stallDelivered || stallNotified)` 改为只认 `_stallDelivered`——`stallNotified`（dlcore 置位，仅表示 stall 事件触发过）不代表投递成功，用它抑制会导致 stall 投递失败时终态也被吞。

### 验证

象限 6（path B）实测：stall 未收束触发 → enqueueSync → 收束 → 超时 → `deliverStallAsync` 异步投递成功（jsonl `deferred-delivery:` + host store `status=resolved`）。与 d4ff2989（修复前丢失）形成对照。

## 3. 遗留（非本次六象限阻塞）

### abort handler 注册失败（task:register-handler）

宿主 log 所有 download 任务报 `[task-registry] no handler for type "download"... registered without abort support`。

- `task:register-handler` 需 `permission: "task.control"`（宿主 L175382 上下文），插件 manifest 只有 `task.write/task.read`
- 导致宿主 `stop_task`/`task:abort` **无法中断 download**（`abort` 返回 `no_handler`, `cancel` 返回 `canceled:false`）
- **0.814 / 0.817.86 均存在，非本次回归**

**但 user 取消通道不受影响**：UI 卡片/管理器按钮走插件自己的 HTTP 路由 `/download/cancel`（manager.js L620 / card.js L205 → routes/download.js L153 固定 `manager.cancel(taskId,"user")`），**不依赖宿主 abort handler**。故象限 4 user 取消可靠。abort handler 失败仅影响宿主的 `stop_task` 通道，可单独跟进。

## 4. 测试判据澄清（重要）

| 通道 | jsonl 痕迹 | 判据 |
|---|---|---|
| **同步注入**（injectForSession → payload.messages） | **无** custom_message；agent 在 assistant 正文/thinking 感知 | `stall-debug injected` + `delivered=true` |
| **宿主异步投递**（deferred:resolve） | `custom_message` + `turn_input_consumption` 配对，deliveryId=`deferred-delivery:` | jsonl custom_message + host store `status=resolved` |

**同步注入不写 jsonl custom_message**——这是与宿主异步 deferred 的本质区别。之前用"jsonl 有无 custom_message"判同步/异步是**错误判据**（0.9.1 时代已修正，本次再确认）。
