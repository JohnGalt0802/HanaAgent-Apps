## 一、坐标系

沿用二维模型：

- **维度 A · 投递时机**：对话**未收束**（unsettled，模型还在跑）/ 已**收束**（settled，模型已停）
- **维度 B · 终态类型**：完成（done）/ 取消（canceled）/ 卡滞（stall）

3 × 2 = 6 个象限，另加象限 7（卡滞 → 恢复 → 完成）。

**v2 与 v1 的差异**：v1 用 steer（同步注入）/ deferred（异步投递）两条通道并区分 suppress 策略；
v2 统一交给宿主 `ctx.tasks`，语义只有一条 `delivery: "next-step"`（不打断在途请求，
下一次输入收集点接收；空闲会话则启动后续回合）。所以「是否 suppress」的判定在 v2 不再适用。

## 四、象限 5/6 的行为（较上一份报告有修正）

**上一份报告**（0.946.2）写的是「卡滞**不投递**」。本轮实测更细，准确表述是**两段式**：

1. **卡滞进行中不投递**——引擎只把状态快照写进 `app-data/hana-downloader/stalled/<taskId>.json`，
   **不惊动模型**。实测落盘内容（中途快照，`state` 仍为 `running`）：
   ```json
   {"taskId":"045187c9-mu0om1ax","state":"running","fileName":"q5-stall.bin",
    "total":100000,"received":1000,"filePath":"D:\\…\\q5-stall.bin",
    "error":null,"canceledBy":null}
   ```
2. **卡滞转为终态时照常投递一次**——`stall-server` 静默 150s 后断流，任务以
   `interrupted` 收终，会话收到一条回执：
   ```
   <hana-background-result status="failed">下载失败：q5-stall.bin（请求被中止）</hana-background-result>
   ```
   日志：`tasks settled | app:hana-downloader:a758ad35-… -> interrupted`

**根因未变**：`ctx.tasks.create` 若要投递到会话（`delivery: "next-step"`）必须携带当前有效的
`callToken`；而 callToken **只在工具 `execute` 期间有效**，下载中途早已过期。所以 v2 的投递模型
天然是「**一次 execute → 一条终态通知**」，中途状态只能靠引擎落盘 + 前端卡片轮询展示。

**结论**：象限 5/6 标为「✅ 行为确认」而非「✅ 通过」——它们验证的是**边界符合预期**，
不是「功能可用」。若将来需要「中途惊动模型」，需要宿主提供不依赖 callToken 的会话投递入口
（或长时间有效的投递票据）。

## 五、附带发现

1. **卡片宽度 450 生效**。宿主 0.978.0 把聊天流卡的信封上限从 300 提到 **774**，
   页面按 450 上报，实测渲染 **449px**（上报值 −1px，规则未变）。
   证据（卡片内 `hana.track` 上报、宿主侧读取）：
   ```json
   {"w":449,"h":45,"dpr":1.75,
    "envW":{"mode":"flexible","max":774},
    "envH":{"mode":"flexible","max":1682},
    "want":450}
   ```
2. **工具结果通道原生可用**（无需任何宿主补丁）。卡片以 `type=plugin_card, channel=app` 进入
   会话投影，`cardInstanceId` 由 App 自带（`sha256(appId:taskId)` 前 20 位），宿主原样采用；
   重启前后、实时与历史投影四处一致。
3. **并发不再合并**。同一回合并发两张卡，投影里各自成块（旧插件时代的 followUp 队列合并问题，
   在工具结果通道上不存在）。
4. **`POST /api/extensions/:ref/reload` 之后工具 RPC 通道仍失效**（本轮实测复现）：
   ```
   App tool "download-file" failed: RPC peer closed; cannot call callback.tools.execute
   ```
   宿主只把这类错误包装成了更友好的文案，机制未变。**开发期验收仍需重启宿主**（约 40 秒）。
5. **pre-step 钩子走正门**（`sdk.hooks.onDecision`），不需要插件时代的 bundle 魔改。
   实测日志：`download rule injected (first) | msgs 228 -> 229`。
