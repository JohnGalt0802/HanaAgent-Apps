# 调研：网盘下载通道（2026-09-20，评估后决定不接入）

## 结论

**不接入。** 理由一句话：这条路的能力天花板由网盘方的授权模型决定，不由我们决定。
百度把第三方关进"应用数据目录"，夸克干脆没有官方口子，第三方方案要用户交出浏览器 Cookie
且随时可能失效。写多少代码都改变不了这个前提。

## 实测事实（本次亲自跑的，非二手）

### 百度 bdpan 3.8.7（官方 CLI，已登录，OAuth）

- `search <关键词> --json` **可以搜整个网盘，不受授权目录限制**。实测搜 "hana" 返回 119 条，
  含 `/各种照片/2026/202604/DSC_3907.JPG` 这类真实路径；字段有
  `path` / `server_filename` / `size` / `isdir` / `server_mtime`，外层是 `{items:[...]}`。
- `ls` / `download` / `cp` / `share` 全部只认 `/apps/bdpan/`。`ls /nope` 直接回
  「路径超出授权目录范围」。
- `download <分享链接>` 是两段流程：解析分享 → 转存到 `/apps/bdpan/{日期}/` → 下载到本地
  （用假链接实测，输出依次是「正在解析分享链接」→ 转存失败）。
- 退出码有坑：人类可读模式失败 `exit=1`；`--json` 模式失败 `exit=0` 但 `code=1`。
  **判定必须读 JSON 的 code，不能信退出码。**
- `whoami --json` → `{authenticated, username, has_valid_token, token_expires_in}`，
  输出是干净 UTF-8。这是现成的登录态检测手段。
- **成功下载时有没有进度输出，未验证**（需要一个真实文件或分享链接才能测）。

**结论：能找，不能搬。**

### 夸克（kuake_cli v1.5.0，第三方 Go 单文件，AGPL-3.0）

- 命令名 `kuake`，Windows 资产 `kuake-v1.5.0-windows-amd64.exe`，退出码 0/1，
  失败也输出 JSON 到 stdout。
- 子命令：`user / list / info / download / upload / create / move / copy / rename / delete /
  share / share-delete / share-list / share-save`。
- **没有搜索子命令。**
- **不支持下载文件夹**（源码 `if isDir { ... "cannot download directory" }`）。
- `list --stream` 返回含 `download_url` 字段（能否脱离 Cookie 直接 HTTP 取，未验证）。
- 下载进度写在 **stderr**：每 500ms 一行 `\rDownloaded 12.34 MB / 56.78 MB (21.7%)`。
- 登录：手工从浏览器 F12 复制整段 Cookie，存 `KUAKE_COOKIE`
  （或 `KUAKE_PUS` + `KUAKE_PUUS`），也支持 `-cookies` 参数与 cwd 下的 `.env`。

**结论：能搬，不能找。**

### 环境与其他候选

- 本机 `bypy`（另一个 Python 版百度网盘工具）**已损坏**：连 `-V` 都无输出、`exit=1`。
- 本机有 Node 24、Python 3.12；**没有 Java、没有 Docker、没有 Go**。
- `qaiu/netdisk-fast-download`（分享链接直链解析服务）把百度/夸克划在**付费专业版**，
  开源版覆盖范围不确定，且需要 Java 运行时。
- `qjfoidnh/BaiduPCS-Go`（第三方，活跃）能下任意目录，但要把完整登录态交给第三方，
  README 自述不提供提速，且普通账号多线程会被百度限速到接近零。

### 两张表摆在一起的图景

| 能力 | 百度 bdpan | 夸克 kuake_cli |
| --- | --- | --- |
| 全盘搜索 | 有 | **没有** |
| 列目录 | 有，仅 `/apps/bdpan/` | 有，全盘 |
| 下载任意文件 | **不行** | 可以（单文件） |
| 下载整个文件夹 | 可以（限目录内） | **不行** |
| 拿文件直链 | 没有 | 有（`list` 的 `download_url`） |
| 下载进度 | 未见输出，疑为静默 | 有，stderr 500ms |
| 登录 | 官方 OAuth | 手工 Cookie |
| 性质 | 官方 | 第三方 AGPL |

百度能找不能搬，夸克能搬不能找，缺的恰好是对方那半。

## 什么条件下值得重开

1. 百度开放"应用数据目录"之外的下载授权，或给出面向第三方 App 的直链接口；
2. 夸克推出官方 CLI / 开放 API / WebDAV；
3. 明确接受第三方 Cookie 方案，并接受它随时失效、以及 AGPL 的商用限制。

## 附：与既有技能的分工（将来若做）

`baidu-drive` 技能已经覆盖"找 + 干"（搜索、列表、转存、下载、分享），
下载器只需要包"下"这一步（长任务、卡片、进度、取消、重试、进管理器）。
两者不重复：技能擅长即时查询，下载器擅长可观测的长任务。
